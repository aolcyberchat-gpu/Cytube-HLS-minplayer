# HiveStream Phase 1B — v12.4.2: Audit Verification + Changelog (for GPT-5.6 Luna / cross-LLM continuity)

Third doc in this series. HIV-000 covered the v12.4.1 test-session findings; HIV-001 was Claude's own line-by-line read of the v12.4.1 harness. This doc covers a *second, independent LLM's* code audit of the same v12.4.1 file (`LLM_Code_Review_of_v12-4-1_txt.md`), what of it checked out against the actual code, what didn't, one bug found during implementation that neither review caught, and the resulting v12.4.2 file (`HiveStream_Phase_1B_Natural_Swarm_Diagnostic_v12-4-2.html`).

Verification method: every claim below was checked directly against the v12.4.1 source (grep, targeted diffs, and for the WebRTC-API claims, current MDN documentation) before being acted on — not accepted on the other LLM's authority. Evidence tiers per the project's convention: SOURCE PROVEN (grep/diff-verified against the file, or against a spec/doc), STRONG INFERENCE, UNPROVEN-OPEN.

## 2. Claims that were directionally right but needed correction once checked

- **"TURN/relay reporting should distinguish discovered from used"** — correct in spirit. The audit didn't specify exactly how; implemented as `networkSummary().turnRelay` (any relay candidate ever seen) vs a new `turnRelayUsed` (the actually-*selected* candidate pair used one, read from `R.webrtc.candidatePairRecords`).
- **"`iceCandidatesGathered` depends on a single fragile source"** — true, but note that fixing #1 (the `now()` bug) already makes that one source start working correctly on its own. Implemented the more robust version anyway (a second, independent evidence source via `getStats()` `local-candidate` records, tracked in a new `iceCandidatesGatheredEvidence` array) rather than relying on a single path staying fixed forever.

## 3. A bug neither review caught, found while implementing the SCTP fix

`RTCIceTransport.getSelectedCandidatePair()` does not return an object with `.id`/`.state` fields — per current MDN documentation it returns `{ local, remote }` (two `RTCIceCandidate` objects). v12.4.1's code read `selected.id`/`selected.state` off this return value, both of which have always been `undefined`. Verified against MDN before writing the fix (both `RTCIceTransport.getSelectedCandidatePair()` and `RTCSctpTransport.transport`/`RTCDtlsTransport.iceTransport`/`.state` shapes). Fixed to read `.local.type`/`.remote.type`/`.local.address`/`.remote.address` instead, which are the fields that actually exist.

Also found while implementing: `summarizeCandidateStat()` (in the main-script IIFE) had its own **third**, independently-written copy of the same address-family misclassification bug — a separate inline check, not a shared helper, so fixing `parseSdpCandidateInventory()`'s copy alone would have left this one live. This one matters more than the first two: it feeds `remoteCandidateStats`, `localCandidateStats`, and `candidatePairRecords` — the `getStats()`-based data this whole audit and the v12.4.2 SCTP work treat as the *authoritative* evidence source. Fixed by sharing one `classifyAddressFamily()` helper (duplicated once per IIFE, matching this file's existing pattern for `mono()`).

One more small thing caught during implementation, not a bug: `compactWebRTC()` didn't expose the new `R.webrtc.unattributedPeerIds` list in its returned object. Added it — otherwise the new peer-correlation-ambiguity tracking (§ below) would have been write-only, never visible in the actual exported JSON.

## 4. Full v12.4.2 changelog

**Critical fix**
- Added a local `now()` inside `installPeerConnectionCapture()`. This was the single highest-value fix in this release.

**Correctness fixes**
- `correlatePeerIdToBrowserPc()` rewritten to build its candidate pool from `pc.__hsV11` records throughout (not just the initial filter). Behavior change: when genuinely ambiguous (more than one open, unclaimed connection could be the peer), it now refuses to guess and logs to a new `R.webrtc.unattributedPeerIds` array instead of silently attributing to the most-recently-created candidate. The "no open connection at all" case is now logged too (previously silent).
- Removed dead code: `attachPC()`, `attachDataChannel()`, and — found only once their sole caller was gone — `parseCandidate()`, `addCandidateRecord()`, `recordState()`, all of which had no other callers anywhere in the file. (`normalizeCandidateType()` is still used elsewhere and was kept.)
- `R` state shape consolidated into one `makeFreshR(opts)` factory. Preserved a real behavioral difference between the two prior copies: `resetRun()` reads live form-input values for `configuration` (stream URL, swarm mode, transport mode, etc.), while the page-load initializer uses static defaults — now handled via `opts.configuration`.
- Restart/timer lifecycle: `clearInterval` calls moved to the top of the Start/Restart handler, unconditionally, before `resetRun()`/`createPlayer()` run.
- `parseSdpCandidateInventory()` and `summarizeCandidateStat()` (two separate, independently-buggy copies) and `candidateSummary()` (already correct) now all share one `classifyAddressFamily()` helper (duplicated once per IIFE — same pattern as `mono()`), correctly returning `"hostname"` for mDNS/non-IP addresses instead of forcing `"IPv4"`.
- Fixed `RTCIceTransport.getSelectedCandidatePair()` field access (see §3).
- `p2pMediaLoaderHlsJs.runtimeVerified` → `runtimePresent` (schema + both call sites).

**New instrumentation**
- Real SCTP/DTLS/ICE transport-chain evidence: `pc.sctp` → `.transport` (`RTCDtlsTransport`) → `.iceTransport` (`RTCIceTransport`), replacing the sender-based lookup. New fields: `connectivity.sctpConnected`, per-connection `stats.sctp` (`state`/`maxMessageSize`/`maxChannels`), `stats.dtlsTransportState`, `stats.iceTransport` (state + selected-pair local/remote candidate types and addresses).
- `getStats()` `local-candidate` records are now captured (previously only `remote-candidate` was), feeding a new `connectivity.iceCandidatesGatheredEvidence` array alongside the (now-working) event-capture path.
- `networkSummary()`: added `turnRelayUsed` alongside the existing `turnRelay`.
- `transportSummary()`: added `requestedMode`, `effectiveMode`, `rescued`.
- `webrtc.unattributedPeerIds`: records every case where peer-ID-to-connection correlation was refused or impossible, with a reason.

**Performance / memory**
- `V12_ARRAY_CAP` (the shared history-buffer cap used across most bounded per-connection arrays): 2000 → 600.
- `pruneOldPeerConnections()`: added, called at the top of `resetRun()`. Keeps only the just-ended run's captured `RTCPeerConnection`s (mutates `window.__HS_V11_PEER_CONNECTIONS` in place — replacing the array reference instead would silently orphan the capture IIFE's own closure, which keeps pushing into the array it originally created). Bounds native-object + history retention to roughly one run of overlap instead of an entire browser-tab session's worth of repeated Start/Restart cycles.
- The live "raw JSON" preview panel in `draw()` now rebuilds every 5th tick (~5s) instead of every tick (~1s); every other panel (identity/manifest/peers/webrtc/scheduler/transport/transfer/storage/log) is unchanged at 1s. `saveJsonToFile()` is untouched — it always calls `publicReport()` fresh at the moment of saving, regardless of this throttle.

**Cosmetic**
- Version strings bumped to 12.4.2 (page title, `<h1>`, header comment, `test.version`, `instrumentation.instrumentationVersion`, `export.exporterVersion`, saved-filename tag).
- Authorship line now credits Claude (Anthropic, Claude Sonnet 5) for the v12.4.2 fixes alongside Elwood Edwards and GPT-5.6 Luna.
